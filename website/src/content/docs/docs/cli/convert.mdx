`sqlquack convert` prints the DuckDB SQL for Snowflake SQL, or refuses it. Every statement it
prints has passed DuckDB's own parse-and-bind check.

## Usage

```bash
sqlquack convert [OPTIONS] [PATH]
```

```bash
sqlquack convert query.sql --builtin-policy
echo "SELECT 1 AS total" | sqlquack convert --builtin-policy --json
```

`PATH` is a SQL file. Without one, or with `-`, `convert` reads standard input. The tables the SQL
reads come from the [project](/docs/project/) in the current folder. The DuckDB SQL goes
to standard output, laid out with each clause on its own line, select items one per line, and
nested queries and long `CASE` expressions indented; short statements stay on one line. Progress,
the known differences and assumptions it relies on, and refusals go to standard error.

```console
$ sqlquack convert revenue.sql --builtin-policy
SELECT
    "ORDERS"."CUSTOMER_ID" AS "CUSTOMER_ID",
    CAST(sum("ORDERS"."TOTAL") AS DECIMAL(24,2)) AS "REVENUE"
FROM "ORDERS" AS "ORDERS"
WHERE ("ORDERS"."STATUS" = 'shipped')
GROUP BY "ORDERS"."CUSTOMER_ID"
sqlquack convert: done, converted under the built-in default
```

## Refusals

A refused statement prints its refusals instead, each as a coded diagnostic, and `convert` exits 1.
Each refusal is one of these:

| Code | Why |
|------|-----|
| [`SQ0002`](/docs/diagnostics/reference/#sq0002) | No verified rule converts the construct yet. |
| [`SQ0003`](/docs/diagnostics/reference/#sq0003) | A rule exists, but not for these operand types. |
| [`SQ0004`](/docs/diagnostics/reference/#sq0004) | A relation or column name is not declared in the project's sources. |
| [`SQ0005`](/docs/diagnostics/reference/#sq0005) | DuckDB cannot express the construct's Snowflake meaning. |
| [`SQ0006`](/docs/diagnostics/reference/#sq0006) | Conversion exceeded its time or size budget. |
| [`SQ0007`](/docs/diagnostics/reference/#sq0007) | The session parameters match no recorded profile. |
| [`SQ0008`](/docs/diagnostics/reference/#sq0008) | The conversion needs a known difference that is refused. |
| [`SQ0009`](/docs/diagnostics/reference/#sq0009) | A select item has no alias, and SQLQuack has not verified the column name Snowflake gives it. |

SQL that does not parse, or that Snowflake rejects, is refused with the same codes as
[`check`](/docs/cli/check/). A `VALUES` list of more than 1,000 rows is refused.

## Options

| Option | Meaning |
|--------|---------|
| `--project <folder>` | The [project](/docs/project/) declaring the tables and functions the SQL reads. Default the current folder. |
| `--session NAME=VALUE` | A Snowflake session parameter of your session, replacing the project's. Repeatable. See [Sessions](/docs/sessions/). |
| `--overrides <path>` | [Replacements](/docs/policy/#replace): a `FUNCTION()` file, or a directory of them, each with `replaces` and `dialect duckdb`. Replaces the project's `overrides/` folder. |
| `--verified-override NAME=SHA256` | An override verified for the body with that hash, as `convert --json` reports. |
| `--compact` | Print each statement on one line instead, in the JSON report too. |
| `--format text\|json`, `--json` | Print the report as text or JSON. |
| `--color auto\|always\|never` | Highlight the SQL and colour diagnostics, as for [`check`](/docs/cli/check/#options). JSON is never coloured. |

{/* config-split: --utc-session and --loud-divergences-only fold into the defaults and --strict. */}

`convert` also takes the policy flags: `--policy`, `--builtin-policy`, `--strict`,
`--utc-session`, `--confirm-declared-offsets`, `--python-runtime` and `--loud-divergences-only`.
See [When something can't convert exactly](/docs/policy/#flags).

## JSON report

With `--json`, `convert` prints one object:

```json
{
  "converted": true,
  "profile": "the built-in default",
  "sql": "SELECT CAST(1 AS DECIMAL(1,0)) AS \"TOTAL\"",
  "refusals": [],
  "divergences": {},
  "assumptions": [],
  "divergence_failures": {},
  "notes": [],
  "python_functions": [],
  "macros": [],
  "overrides": []
}
```

`sql` is laid out as the text output prints it, or on one line with `--compact`. `macros` lists
the statements to run first, in order: those creating the [helper macros](/docs/helper-macros/)
the SQL calls, then your override macros. The text output prints them ahead of the SQL. A refusal in
`refusals` carries the same [diagnostic fields](/docs/diagnostics/overview/#json-output).

## Exit status

| Code | Meaning |
|------|---------|
| `0` | Converted. |
| `1` | Something was refused; the reasons are on standard error. |
| `2` | It could not run: bad arguments, an unreadable file, a missing `--policy` file or an invalid policy file, or input without SQL. |
