## Install

SQLQuack installs from PyPI with Python 3.12 or newer. The package ships the `sqlquack` command and
the [Python](/docs/python/) library, with DuckDB's library beside them.

```bash
pip install sqlquack
sqlquack --version
```

### Build from source

To build the command line from the repository instead, use Rust. The repository pins its toolchain
in `rust-toolchain.toml`, which `rustup` installs on first use.

```bash
git clone https://github.com/sqlstack-io/sqlquack
cd sqlquack
cargo build --release -p sqlquack
```

The binary links DuckDB's prebuilt shared library, which the build downloads to
`target/duckdb-download/<target triple>/<DuckDB version>`. `cargo run` puts it on the library path
for you:

```bash
cargo run --release -p sqlquack -- check query.sql
```

To run `target/release/sqlquack` directly, point the library path at that directory:

```bash
LD_LIBRARY_PATH=target/duckdb-download/x86_64-unknown-linux-gnu/v2.0.0 target/release/sqlquack check query.sql
```

Use `DYLD_LIBRARY_PATH` on macOS and `PATH` on Windows.

## Check a file

`check` needs no schema. It parses the SQL and reports what Snowflake would reject.

```sql
-- orders.sql
SELECT customer_id, SUM(total) AS revenue
FROM orders
WHERE status = 'shipped'
GROUP BY customer_id
QUALIFY revenue > 100
```

```console
$ sqlquack check orders.sql
error[SQ0203]: QUALIFY needs a window function
 --> orders.sql:5:1
  |
5 | QUALIFY revenue > 100
  | ^^^^^^^^^^^^^^^^^^^^^ QUALIFY is used without a window function in the SELECT list or QUALIFY
  |
  = help: move the condition to WHERE or HAVING, or filter on a window function's result
sqlquack check: found 1 problem
```

Move the condition to `HAVING SUM(total) > 100` and `check` reports no problems.

## Convert a file

Conversion types every expression, so it needs the columns and Snowflake types of the relations a
statement reads. Declare them in a source file under `sources/` in the folder you run `sqlquack`
from (see [Projects](/docs/project/)):

```yaml
# sources/orders.yml
sources:
  - name: orders
    columns:
      - name: order_id
        type: NUMBER(38,0)
      - name: customer_id
        type: NUMBER(38,0)
      - name: status
        type: VARCHAR
      - name: total
        type: NUMBER(12,2)
      - name: ordered_at
        type: TIMESTAMP_NTZ
```

```console
$ sqlquack convert revenue.sql --builtin-policy
SELECT
    "ORDERS"."CUSTOMER_ID" AS "CUSTOMER_ID",
    CAST(sum("ORDERS"."TOTAL") AS DECIMAL(24,2)) AS "REVENUE"
FROM "ORDERS" AS "ORDERS"
WHERE ("ORDERS"."STATUS" = 'shipped')
GROUP BY "ORDERS"."CUSTOMER_ID"
sqlquack convert: done, converted
```

The DuckDB SQL goes to standard output and the progress lines to standard error, so
`sqlquack convert revenue.sql … > revenue.duckdb.sql` keeps only the SQL.

Some Snowflake behaviour has no exact match in DuckDB, such as `HASH`. For each of these known
differences you refuse it, allow it or replace it with your own SQL, in `sqlquack.toml` in the
current directory or the file `--policy` names. Without one, or with `--builtin-policy`, `convert`
uses the built-in default: it refuses every known difference except the clock and those that can
only fail with an error, such as arithmetic past its range or JSON DuckDB might read differently,
which convert with a warning. See [When something can't convert exactly](/docs/policy/).
