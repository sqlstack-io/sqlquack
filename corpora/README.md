# Corpora

SQL that tests and development checks read. Nothing here is recorded evidence; that lives in
`evidence/`. There are two kinds of corpus.

## Conversion regression corpora

Snowflake statements with the outcome SQLQuack gives each. The `everyday_corpus` test in
`crates/sqlquack` fails when an outcome changes, and `make corpus-rerecord` rewrites the recorded
outcomes from the current converter. Run it in the change that moves an outcome and commit the
corpora with it.

| Directory | Contents |
|---|---|
| `basics/` | Basic statements a first-time user types, each in several spellings that mean the same statement. Generated by `scripts/generate_basics_corpus.py`, then re-recorded; do not edit by hand. |
| `everyday/` | Everyday queries as a demo visitor or a dbt project writes them, over the tables in `sources/tables.yml`, with Snowflake's own verdicts in `snowflake-receipts.json`. |
| `everyday-models/` | dbt-style models over `sources/tables.yml`, with the same fields as `everyday/`. |

## Development check inputs

Inputs of checks that never ship. Their outcomes are not recorded here.

| Directory | Read by |
|---|---|
| `polyglot-check/` | `tools/sqlquack-polyglot-check`, which proves that `sqlquack-syntax` parses exactly as polyglot does, and the fuzz corpus seed (`scripts/fuzz_corpus`). `expected_differences.toml` lists the reviewed differences. The `*.NOTICE` files and `THIRD_PARTY_NOTICES` give the sources' licences. |
| `duckdb-core/` | The DuckDB parser's corpus tests in `crates/sqlquack-syntax-duckdb`; see its README. |
| `databricks-core/` | The acceptance corpus for the Databricks parser, each statement tagged with the catalogue forms it uses; no test reads it yet. See its README. |
